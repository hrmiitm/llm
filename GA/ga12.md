## Positional Encodings: APE, RPE, RoPE, & ALiBi

### Q1 — Length Extrapolation with Absolute Position Encodings

**Consider a problem of length extrapolation using an Absolute Position Encoding (APE) scheme. Suppose the context length of a model during training is 512. Which of the following approaches allows the model to extrapolate to a context length of 1024 tokens?**

- [x] Fixed Sinusoidal Encoding
- [ ] Parameterized APE
- [ ] ALiBi
- [ ] T5

<details>
<summary><b>Answer & Solution</b></summary>

**Answer:** Fixed Sinusoidal Encoding

#### ✏️ Step-by-Step Solution

**Step 1 — Understand the constraint in the question.**

The question specifies using an **Absolute Position Encoding (APE)** scheme:
- **ALiBi** and **T5** are **Relative Position Encodings (RPE)**, not APE schemes. Hence, they are disqualified by the question constraint.
- This leaves only **Fixed Sinusoidal Encoding** and **Parameterized APE**.

**Step 2 — Compare Parameterized APE vs. Fixed Sinusoidal APE.**

1. **Parameterized (Learned) APE (e.g., BERT, GPT-2):**
   - Learns a lookup embedding matrix $P \in \mathbb{R}^{T_{\text{train}} \times d}$.
   - For a model trained with $T_{\text{train}} = 512$, the lookup table only contains 512 rows ($p_0, p_1, \dots, p_{511}$).
   - At inference length 1024, positions $512 \dots 1023$ have **no initialized or trained weights**. The model cannot process them without re-training or interpolation.
2. **Fixed Sinusoidal Position Encoding (Vaswani et al., 2017):**
   - Position vectors are generated using fixed mathematical trigonometric formulas:
     $$PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right)$$
     $$PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right)$$
   - Because this function is continuous and deterministic, it can be evaluated for any arbitrary integer $pos \ge 512$ without needing any trained parameters.

**Conclusion:** Only **Fixed Sinusoidal Encoding** allows length extrapolation among APE schemes.

$`\displaystyle \boxed{\text{Fixed Sinusoidal Encoding}}`$

### Q2 — Relative Position Information in APE Schemes

**The statement that *"in principle, no APE schemes can encode the relative position information of tokens in the input sequence"* is:**

- [ ] True
- [x] False

<details>
<summary><b>Answer & Solution</b></summary>

**Answer:** False

#### ✏️ Step-by-Step Solution

**Step 1 — Understand the theoretical capability of sinusoidal APE.**

In Section 3.5 of Vaswani et al. (2017, *"Attention Is All You Need"*), the authors chose sinusoidal encodings specifically because they hypothesized it would allow the model to easily learn to attend by **relative positions**:
> *"For any fixed offset $k$, $PE_{pos+k}$ can be represented as a linear function of $PE_{pos}$."*

**Step 2 — Mathematical proof using trigonometric identities:**

Using the angle addition formulas:
$$\sin(pos + k) = \sin(pos)\cos(k) + \cos(pos)\sin(k)$$
$$\cos(pos + k) = \cos(pos)\cos(k) - \sin(pos)\sin(k)$$

This means there exists a $2 \times 2$ orthogonal rotation matrix $M_k$:
$$\begin{pmatrix} PE_{(pos+k, 2i)} \\ PE_{(pos+k, 2i+1)} \end{pmatrix} = \begin{pmatrix} \cos(\omega_i k) & \sin(\omega_i k) \\ -\sin(\omega_i k) & \cos(\omega_i k) \end{pmatrix} \begin{pmatrix} PE_{(pos, 2i)} \\ PE_{(pos, 2i+1)} \end{pmatrix}$$

When the self-attention layer computes query-key dot products:
$$(\mathbf{x}_i + \mathbf{p}_i) W_Q W_K^T (\mathbf{x}_j + \mathbf{p}_j)^T$$
the positional interaction term $\mathbf{p}_i W_Q W_K^T \mathbf{p}_j^T$ directly reflects the relative distance $i - j$.

**Conclusion:** APE schemes **can** encode relative position information. The statement is **False**.

$`\displaystyle \boxed{\text{False}}`$

</details>

### Q3 — Tensor Dimension of $P_K$ in Relative Position Encoding

**The pre-attention score $e_{ij}$ in Relative Position Encoding (RPE) can be written in matrix form as follows:**

$$E = X W_Q (X W_K + P_K)^T$$

**What will be the dimension of $P_K$? In all the options, $T$ denotes context length.**

- [ ] $T \times T \times T \times d_{\text{model}}$
- [x] $T \times T \times d_{\text{model}}$
- [ ] $T \times d_{\text{model}}$
- [ ] $T \times T$

<details>
<summary><b>Answer & Solution</b></summary>

**Answer:** $T \times T \times d_{\text{model}}$

#### ✏️ Step-by-Step Solution

**Step 1 — Look at the scalar formulation of Shaw et al. (2018) RPE:**

In relative position encoding, the pre-attention scalar score between query token at position $i$ and key token at position $j$ is:
$$e_{ij} = \frac{\mathbf{q}_i (\mathbf{k}_j + \mathbf{a}_{ij}^K)^T}{\sqrt{d_k}} = \frac{\mathbf{x}_i W_Q (\mathbf{x}_j W_K + \mathbf{a}_{ij}^K)^T}{\sqrt{d_k}}$$
where $\mathbf{a}_{ij}^K \in \mathbb{R}^{d_k}$ is the relative position embedding representing the distance $j - i$.

**Step 2 — Analyze the indices of $\mathbf{a}_{ij}^K$:**

- Index $i \in \{1, 2, \dots, T\}$ (query token position)
- Index $j \in \{1, 2, \dots, T\}$ (key token position)
- Vector dimension of each $\mathbf{a}_{ij}^K = d_{\text{model}}$ (or $d_k$)

**Step 3 — Express in matrix/tensor form:**

To write the attention computation across all queries $i$ and keys $j$ simultaneously:
$$E = X W_Q (X W_K + P_K)^T$$
For every pair $(i, j)$ in the $T \times T$ attention matrix, there must be a corresponding vector of dimension $d_{\text{model}}$.
Thus, $P_K$ must be a 3D tensor of shape:
$$\text{Dimension}(P_K) = T \times T \times d_{\text{model}}$$

$`\displaystyle \boxed{T \times T \times d_{\text{model}}}`$

</details>

### Q4 — Parameter Efficiency in Relative Position Encodings

**Suppose the context length of a model is 16K. Amongst the given choices, choose the RPE schemes that require the least number of parameters to encode the relative position information of the tokens:**

- [x] T5-bias
- [ ] Transformer-XL
- [ ] Shaw RPE
- [ ] ALiBi

<details>
<summary><b>Answer & Solution</b></summary>

**Answer:** Options 1 and 4 — T5-bias and ALiBi.

#### ✏️ Step-by-Step Solution

**Step 1 — Examine the parameter count of each RPE scheme:**

| Position Scheme | How Relative Position is Encoded | Parameter Count for Context 16K |
|---|---|:---:|
| **ALiBi** (Press et al., 2021) | Adds a non-learned linear penalty $m \cdot (j - i)$ directly to attention logits. | **0 parameters** (Completely parameter-free!) |
| **T5-bias** (Raffel et al., 2020) | Maps relative distances into 32 logarithmic buckets; learns a single scalar bias per bucket per head. | **32 scalars per head** (Tiny, constant regardless of 16K context) |
| **Transformer-XL** (Dai et al., 2019) | Learns relative positional embedding matrix $R \in \mathbb{R}^{16000 \times d}$ plus global bias vectors $\mathbf{u}, \mathbf{v} \in \mathbb{R}^d$. | **$16{,}000 \times d$ parameters** (Large!) |
| **Shaw RPE** (Shaw et al., 2018) | Learns relative position vectors $\mathbf{w}^K, \mathbf{w}^V \in \mathbb{R}^{(2k+1) \times d}$ for clipped distance $k$. | **$2k \times d$ vector parameters** |

**Step 2 — Compare:**
- **ALiBi** has **0** parameters.
- **T5-bias** has only **32 scalar values** per head (independent of context length).
- Transformer-XL and Shaw RPE require full embedding matrices.

Therefore, **ALiBi** and **T5-bias** require the least number of parameters.

</details>

### Q5 — Fixed (Non-Learnable) Position Encoding Schemes

**Select all the fixed position encoding schemes (i.e., it has no learnable components). Note that you may refer to the original papers if required. Avoid going through implementations of the papers in DL frameworks:**

- [ ] T5-bias
- [ ] Transformer-XL
- [x] RoPE
- [x] ALiBi

<details>
<summary><b>Answer & Solution</b></summary>

**Answer:** Options 3 and 4 — RoPE and ALiBi.

#### ✏️ Step-by-Step Solution

**Step 1 — Identify the mathematical nature of each scheme:**

1. **RoPE (Rotary Position Embedding, Su et al., 2021):**
   - Applies a deterministic 2D rotation to query and key vectors:
     $$\tilde{\mathbf{q}}_m = R_{\Theta, m}^d \mathbf{q}_m, \quad \tilde{\mathbf{k}}_n = R_{\Theta, n}^d \mathbf{k}_n$$
   - The rotation angles $\theta_i = 10000^{-2(i-1)/d}$ are fixed geometric frequencies (identical to sinusoidal encodings).
   - **No parameters are learned during training.** $\to$ **Fixed** ✅
2. **ALiBi (Attention with Linear Biases, Press et al., 2021):**
   - Modifies the attention score by subtracting a fixed linear penalty proportional to token distance:
     $$\text{Softmax}\left(\mathbf{q}_i \mathbf{k}_j^T - m \cdot |i - j|\right)$$
   - The slope $m = 2^{-\frac{8}{h} \cdot \text{head\_idx}}$ is a static geometric sequence chosen before training.
   - **Zero learnable parameters.** $\to$ **Fixed** ✅
3. **T5-bias:** Learns scalar bucket weights during training. $\to$ **Learnable** ❌
4. **Transformer-XL:** Learns global bias vectors $\mathbf{u}, \mathbf{v}$ and embedding projections. $\to$ **Learnable** ❌

**Conclusion:** **RoPE** and **ALiBi** are the fixed, non-learnable schemes.

</details>

### Q6 — Inference Without Positional Embeddings (NoPos)

**Suppose that a team pre-trains a decoder model using CLM (Causal Language Modelling) objective using the APE scheme. However, during inference, one of the team members suggested not to add the position information for the following reasons:**

- **[I]** *The causal mask in the decoder itself encodes the position information as suggested in the NoPos paper.*
- **[II]** *Adding no additional positional embedding to each token will also help increase the inference speed marginally.*

**Which of the following statements is (are) correct?**

- [x] I is a correct reason but it can't be used only during inference as it hurts the performance
- [x] II is a correct statement
- [ ] I is a correct reason as it can be used during inference without hurting the performance
- [ ] II is not a correct statement

<details>
<summary><b>Answer & Solution</b></summary>

**Answer:** Options 1 and 2 are correct.

#### ✏️ Step-by-Step Solution

**Step 1 — Evaluate Reason [I] (The NoPos argument):**

- In the paper *"How Much Position Information Do Causal Language Models Need?"* (Haviv et al., 2022 — **NoPos**), the authors proved that causal masking in decoder-only transformers breaks token permutation symmetry. Each token $t$ attends to exactly $t$ prior tokens, allowing the network to implicitly infer token order without any explicit positional encodings.
- **However:** If a model was pre-trained **with** APE, its internal weights have been optimized assuming that embedding vectors have positional vectors added ($\mathbf{x}_t + \mathbf{p}_t$).
- Suddenly dropping $\mathbf{p}_t$ **only during inference** creates a disastrous train-test distribution shift, destroying attention patterns and degrading performance severely.
- Therefore, **[I] is a theoretically correct reason, but it cannot be applied only at inference time.** $\to$ **Statement 1 is True** ✅.

**Step 2 — Evaluate Reason [II] (Inference speedup):**

- At each generated token, skipping the element-wise vector addition $\mathbf{e}_t = \mathbf{x}_t + \mathbf{p}_t$ eliminates $d_{\text{model}}$ addition operations.
- While small compared to attention matrix multiplications, this does provide a marginal computational saving.
- Therefore, **[II] is a correct statement.** $\to$ **Statement 2 is True** ✅.

</details>
